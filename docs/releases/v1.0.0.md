# svg-motion-kit v1.0.0: one report, safe fixes

Eight Claude Code skills that take a frontend from "it works" to "it's finished". They read your real theme, find where the UX needs help, add animated SVG that fits, and review security, accessibility, performance, design and polish with evidence. You choose which fixes to apply, one diff at a time.

```text
/plugin marketplace add James-Chirawat/svg-motion-kit
/plugin install svg-motion-kit@svg-motion-kit
```

Then ask: *"audit my site before launch"* / *"ตรวจเว็บทั้งหมดก่อนขึ้น production"*, followed by *"fix F2 and F5"*.

## Skills

| Skill | What it does |
|---|---|
| `audit` | Runs every area, writes one prioritised report with numbered findings, then fixes the ones you pick (each diff checked and re-verified) |
| `theme-extract` | Reads your real tokens: Tailwind v3/v4, CSS variables, shadcn, dark mode, fonts |
| `svg-motion` | Scouts empty, loading, error, success, offline and upload moments, renders 8 theme-true templates, validates them, and exports React, Vue or Svelte components |
| `design-lint` | Flags the generic AI look and proposes three grounded design directions |
| `ui-audit` | UX states, forms, tap targets, WCAG contrast from your theme, accessibility basics |
| `perf-audit` | Images, Thai fonts, request waterfalls and N+1 calls, caching, bundles, third-party scripts |
| `security-audit` | Masked secret scan, committed `.env`, public env leaks, XSS sinks (incl. uploaded SVG), unauthenticated routes and actions, headers |
| `polish-audit` | Metadata, OG image, favicon, 404 and error pages, robots and sitemap, i18n, design-system drift, code health |

## How it was tested

- **Unit tests:** 59, on Node 18 and 22.
- **Fixtures:** 9 example projects, each with planted problems.
- **Real projects:** every audit was tuned against 6 real projects for false positives.
- **Live headless runs** in Thai and English. One full audit and fix run went 72 → 76.
- **Eval suite:** 7 cases, with correct triggering in all of them, including the case where nothing should fire.

Details are in `docs/TESTING.md`.

## Honest limits

These are static, code-level checks. They do not replace Lighthouse (real Core Web Vitals), `npm audit` (dependency CVEs), a penetration test, or looking at the site in a browser. Every report says what it didn't cover. Scripts are plain Node 18+, with no dependencies and no network access.
